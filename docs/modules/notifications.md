# Module Map — `src/_common/modules/notifications`
_Ported from the reference app on 2026-08-07 (migration step 13) and corrected for this repo.
Originally generated by a review agent on 2026-06-23 at commit 33ec20a._

> **This module is not app code.** Since the reference generated this map, notifications moved into
> the framework submodule at `src/_common/modules/notifications/`, which owns `api/`, `component/`,
> `composable/`, `dto/`, `utils/` and the `reminderPreference/` sub-feature. Paths below are relative
> to that root, and **none of it may be edited from this repo** — see CLAUDE.md.
>
> What this app supplies: `src/app/notifications/notificationTypeMeta.ts` (the type → icon/colour/route
> map, handed over at boot via `installFramework`), the `#actions` slot in `App.vue` that mounts the
> bell, and the `reminderPreferences` route spread into `src/router.ts`.

## Purpose
In-app + Web Push notification system. Renders a bell dropdown in the top bar (any authenticated user)
that lists the current user's notifications over a real-time SignalR hub, supports optimistic mark-as-read,
and click-through navigation per notification type. A companion push-subscription flow registers the device
for Web Push. No dedicated routes/views — surfaced entirely through the global top bar.

> Note: the stateful composables now live in this module's own `composable/` folder, not in
> `_common/composable/general/` as the original map said.

## Routes & Views
The bell itself has no route — it is mounted globally through `AppTopBar`'s `#actions` slot, which
`App.vue` fills. The module does export one route table, `notifications.routes.ts`:

| Route path | Name | View file |
|---|---|---|
| `/nastavenia/pripomienky` | `reminderPreferences` | `reminderPreference/view/ReminderPreferencesView.vue` |

The framework's `UserMenu` links to it by name, so it must stay registered in `src/router.ts`.

## Stores (Pinia)
_None in this module._ Real-time state is held as module-level `ref`s inside the `useNotifications` composable (singleton), not a Pinia store.

## Composables
Both live under this module and are **global singletons** (module-level `ref`s, not Pinia):

| Composable | Path | Purpose |
|---|---|---|
| `useNotifications` | `composable/useNotifications.ts` | Holds `notifications`/`unreadCount`/`isConnected`/`isLoading`; owns the SignalR `HubConnection` (`/hubs/notifications`, `withCredentials`); `connect`/`disconnect`/`loadNotifications`/`markRead`/`markAllRead`; snackbars incoming notifications. |
| `usePushNotifications` | `composable/UsePushNotifications.ts` | Web Push subscribe/unsubscribe, permission + support detection; registers the service worker. `initPushSupport()` is **async**. |

## API composables & endpoints
Bare exported async functions (not `useXxx` factories), all using the shared `API` axios instance.

| Module | Entity | Functions | Backend routes hit |

| `api/PushNotificationsApi.ts` | push-subscription | `registerPushSubscription`, `unsubscribePushSubscription` | `POST /push-subscription`, `POST /push-subscription/unsubscribe` |

## Depends on (`_common` + cross-module)
- `notificationTypeMeta` — `utils/notificationTypeMeta.ts` (in-module): `notificationIcon` / `notificationIconColor` / `notificationRoute`, mapping a notification
  `type` → FontAwesome icon + theme colour + `RouteLocationRaw`. The **map itself** is app-owned and injected: `src/app/notifications/notificationTypeMeta.ts`,
  passed to `installFramework` as `notificationTypeMeta`.
- `serviceWorker` util — `src/_common/utils/serviceWorker.ts` (via `usePushNotifications`).
- `useSnackbar` — `src/_common/composable/general/SnackbarComposable.ts` (via `useNotifications`).
- `API` axios instance — `src/_common/axiosConfig.ts`.
- `@microsoft/signalr`, `dayjs` (+ `relativeTime`, `sk` locale).
- i18n keys: `notifications.*` and `reminderPreference.*` come from `src/_common/_locales/common.sk.ts`, spread by `src/locales/SK.ts`. **They have no EN
  translation** — the framework ships these Slovak-only.
- `VITE_VAPID_PUBLIC_KEY` must be set for Web Push subscription to work; the key is read from the
  environment, not fetched from the backend.

## Assumed / used backend endpoints
- `GET /notification/mine` → `NotificationResponse[]` (used)
- `PATCH /notification/{id}/read` (used)
- `PUT /notification-preference` body `{ type, channel, enabled }` — **assumed-but-unverified; no caller in FE (dead export).**
- `POST /push-subscription` body `{ endpoint, p256dh, auth, userAgent? }` (used)
- `POST /push-subscription/unsubscribe` body `{ endpoint }` (used)
- SignalR hub: `{VITE_API_URL}/hubs/notifications`, server method `ReceiveNotification` (used)
